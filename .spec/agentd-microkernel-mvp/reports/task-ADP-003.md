## What was implemented

- `manifest.rs`: `adapter.manifest.json` parser — requires
  `manifest_version=1`, `kind="adapter"`, `runtime.type="process"`;
  `implements` entries are `"port_id@major"` strings parsed into typed
  `PortImpl`; capabilities flatten `requested_capabilities` groups.
- `registry.rs`: `bundle.lock` is a sorted `sha256:<hex> <path>` inventory
  generated by `write_lock`; `compute_bundle_digest` re-verifies every
  listed file's sha256 on disk, rejects symlinks escaping the canonical
  bundle root, and derives
  `sha256("agentos.bundle.v1\n" ++ manifest_digest ++ "\n" ++ lock_bytes)`
  — the registration key is `(adapter_id, version, bundle_digest)`.
- `register()` persists manifest digest + implemented ports/caps with
  `conformance_state=Untested`; duplicate identity -> `Conflict`.
- `verify_for_spawn()` re-computes the digest *immediately before* spawn;
  drift -> `FailedPrecondition`; resolved entrypoint must canonicalize
  inside the bundle root. AC met: name/version alone never authorizes
  execution — execution always flows through the digest-verified
  `VerifiedBundle`.

## Evidence

`cargo test -p adapter-registry` (12 tests): registration persists
identity; mutating any bundle byte changes the digest; same name/version
with different digest registers as a distinct identity; spawn-time digest
mismatch rejected; entrypoint escape rejected; lock traversal/unsorted/
duplicate entries rejected.
