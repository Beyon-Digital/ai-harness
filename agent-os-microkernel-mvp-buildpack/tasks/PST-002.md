# PST-002 — Define KernelStore transaction interfaces

**Phase:** `persistence`  
**Depends on:** [FND-003](FND-003.md), [FND-004](FND-004.md)

## Goal

Define object-safe/asynchronous transaction contracts that allow the command coordinator to make multi-entity atomic mutations without exposing SQLite.

## Required outputs / expected code locations

- `crates/kernel-store/src/lib.rs`
- `crates/kernel-store/src/txn.rs`
- `crates/kernel-store/src/repositories.rs`

## Normative inputs

- Use the component specs linked from the goal/steps and `DECISIONS.md`.

## Implementation steps

1. Define `KernelStore`, `KernelReadTxn`, `KernelTxn`.
2. Expose typed repository methods for runs, graph, effects, resources, timers, security, config, idempotency, event stream heads/outbox.
3. Transaction carries expected daemon fencing epoch.
4. Commit consumes transaction; rollback is explicit or Drop-safe.
5. Design interfaces around domain operations, not generic string key/value.

## Required tests

- `compile-time/object-safety tests`
- `mock transaction implementation in testkit`

## Acceptance criteria

- [ ] Command coordinator can perform a representative run+effect+outbox+idempotency mutation in one transaction interface.

## Forbidden shortcuts

- Do not add arbitrary SQL escape hatch to kernel callers.
