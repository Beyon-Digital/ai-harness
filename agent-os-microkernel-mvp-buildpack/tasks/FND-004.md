# FND-004 — Implement stable error model

**Phase:** `foundation`  
**Depends on:** [FND-001](FND-001.md)

## Goal

Create a single typed error taxonomy usable across kernel crates and map it to gRPC status later without losing machine-readable codes.

## Required outputs / expected code locations

- `crates/errors/src/lib.rs`
- `crates/errors/src/codes.rs`

## Normative inputs

- Use the component specs linked from the goal/steps and `DECISIONS.md`.

## Implementation steps

1. Implement ErrorCode and RetryDisposition from `specs/error-model.md`.
2. Carry correlation ID and structured details.
3. Provide constructors for revision conflict, fencing rejection, capability unsupported, idempotency conflict, effect unknown, workspace lease conflict.
4. Do not include secret-bearing arbitrary Debug payloads in errors.

## Required tests

- `unit tests for code/retry mapping`
- `serialization tests if error envelope is serialized`

## Acceptance criteria

- [ ] All kernel crates can depend on errors crate without cycles.
- [ ] Retry safety is represented structurally.
