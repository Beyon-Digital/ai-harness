# SEC-003 — Implement immutable approval request/response flow

**Phase:** `security`  
**Depends on:** [SEC-002](SEC-002.md), [CMD-001](CMD-001.md)

## Goal

Persist approval requests whose authorization cannot be replayed against changed content.

## Required outputs / expected code locations

- `crates/approvals/src/lib.rs`
- `crates/kernel-store-sqlite/src/repos/approvals.rs`

## Normative inputs

- Use the component specs linked from the goal/steps and `DECISIONS.md`.

## Implementation steps

1. Canonicalize/hash exact approval request fields.
2. Create pending approval through command transaction and outbox event.
3. Respond by matching request ID + digest + expiry + unresolved state + responder identity.
4. Persist one terminal response.
5. Expose approval result to blocked command/run through normal events/state.

## Required tests

- `digest mismatch rejected`
- `expired request rejected`
- `double response rejected`
- `changed bundle/config digest invalidates prior approval`

## Acceptance criteria

- [ ] Approval is never represented internally as only `bool approved`.
