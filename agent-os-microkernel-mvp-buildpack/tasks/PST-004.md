# PST-004 — Implement OS daemon lock and durable fencing epoch

**Phase:** `persistence`  
**Depends on:** [PST-003](PST-003.md), [FND-005](FND-005.md)

## Goal

Guarantee one authoritative local daemon and give all workers a durable daemon fencing epoch.

## Required outputs / expected code locations

- `crates/agentd/src/lock.rs`
- `crates/kernel-store-sqlite/src/fence.rs`
- `crates/identity/src/daemon.rs`

## Normative inputs

- Use the component specs linked from the goal/steps and `DECISIONS.md`.

## Implementation steps

1. Acquire exclusive file lock before serving work.
2. Inside KernelStore increment/claim singleton daemon fencing epoch for this daemon instance.
3. Heartbeat/lease expiry is persisted for diagnostics/recovery; OS lock is primary local exclusion.
4. All write transactions carry/assert current daemon epoch.
5. On lost lock/fence, daemon transitions to draining and refuses new authoritative work.

## Required tests

- `two-process lock exclusion integration test`
- `fencing epoch increments after restart`
- `stale epoch write rejected`

## Acceptance criteria
