# EFF-003 — Implement effect executor leases and fencing

**Phase:** `effects`  
**Depends on:** [EFF-002](EFF-002.md), [PST-004](PST-004.md)

## Goal

Guarantee one current executor can authoritatively advance an effect.

## Required outputs / expected code locations

- `crates/effects/src/executor.rs`
- `crates/kernel-store-sqlite/src/repos/effect_claims.rs`

## Normative inputs

- Use the component specs linked from the goal/steps and `DECISIONS.md`.

## Implementation steps

1. Atomically claim eligible Prepared/expired Claimed effect with executor ID, lease expiry, monotonically increasing fencing token.
2. Persist Dispatched before external call.
3. Every acknowledge/fail/unknown transition checks executor fencing token.
4. Expired stale executor result is diagnostic only and cannot commit.
5. Executor respects daemon fencing epoch as an outer fence.

## Required tests

- `100-worker single-current-claim test`
- `stale executor acknowledge rejected`
- `lease expiry/reclaim test`
- `daemon fence change rejects old executor`

## Acceptance criteria

- [ ] At most one fencing token can authoritatively progress an effect at a time.
