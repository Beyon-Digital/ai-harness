# QUE-001 — Implement MessageQueuePort and in-memory generation-global adapter

**Phase:** `queue`  
**Depends on:** [FND-002](FND-002.md), [FND-003](FND-003.md)

## Goal

Provide the inception queue contract and a non-durable in-memory adapter for internal/MVP uses without making the queue authoritative for run correctness.

## Required outputs / expected code locations

- `crates/message-queue/src/lib.rs`
- `crates/message-queue/src/in_memory.rs`

## Normative inputs

- `DECISIONS.md`
- `contracts/` port/catalog contracts
- relevant component specs under `specs/`

## Implementation steps

1. Generate/use the canonical `message-queue@1` types.
2. Implement bounded in-memory channels keyed by stream/subscription.
3. Support publish, consume, ack, nack semantics sufficient for fixtures.
4. Declare capabilities: non-durable, no replay, no strict cross-restart guarantees.
5. Ensure worker restarts derive truth from KernelStore rather than queue contents.

## Required tests

- `publish/consume/ack/nack tests`
- `bounded backpressure test`
- `adapter reports durable=false/replay=false`

## Acceptance criteria

- [ ] Queue payload identity is stable and duplicate message IDs are handled deterministically according to the adapter contract.
- [ ] No canonical runtime mutation depends solely on queue delivery.
- [ ] Adapter capability document truthfully reports in-memory limitations.

## Forbidden shortcuts

- Do not bypass the canonical port semantics to make the fixture pass.
- Do not claim durability/security capabilities not actually implemented.
- Follow all prohibited shortcuts in `AGENTS.md`.
