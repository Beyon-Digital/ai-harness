# FND-003 — Implement domain IDs, core enums, and immutable value types

**Phase:** `foundation`  
**Depends on:** [FND-002](FND-002.md)

## Goal

Create strong internal Rust types around canonical protocol fields so kernel APIs do not traffic in unvalidated strings.

## Required outputs / expected code locations

- `crates/domain/src/ids.rs`
- `crates/domain/src/run.rs`
- `crates/domain/src/effect.rs`
- `crates/domain/src/security.rs`
- `crates/domain/src/resource.rs`

## Normative inputs

- Use the component specs linked from the goal/steps and `DECISIONS.md`.

## Implementation steps

1. Implement UUIDv7-backed newtypes for persisted IDs.
2. Implement conversions to/from generated protobuf types with validation.
3. Implement RunState, RecoveryDisposition, WorkspaceAccessMode, effect semantics, Sensitivity and RetentionClass.
4. Add typed Revision/Epoch/Sequence wrappers or validated newtypes to prevent accidental cross-use where practical.
5. No DB or transport dependencies in domain crate.

## Required tests

- `round-trip protobuf conversion tests`
- `invalid enum/ID tests`
- `UUID uniqueness/time-order sanity test`

## Acceptance criteria

- [ ] Internal APIs can use typed IDs/states without raw string parsing.
- [ ] Unknown protobuf enum values fail safely rather than mapping to an unsafe default.
