# EVT-004 — Implement durable Live Event Bus and lag semantics

**Phase:** `events`  
**Depends on:** [EVT-003](EVT-003.md)

## Goal

Provide bounded in-process subscriptions without allowing slow clients to block runtime or silently skip durable history.

## Required outputs / expected code locations

- `crates/events/src/live_bus.rs`

## Normative inputs

- Use the component specs linked from the goal/steps and `DECISIONS.md`.

## Implementation steps

1. Publish durable event only from dispatcher after journal acceptance.
2. Maintain subscriber cursor separately from channel internal position.
3. On lag/overflow return explicit `SubscriberLagged { resume_from }` and close that subscription.
4. Create separate lossy channel/type for ephemeral telemetry.
5. Never advance durable cursor for undelivered event.

## Required tests

- `slow subscriber lag test`
- `resume from Event Journal test`
- `ephemeral drop metric test`

## Acceptance criteria

- [ ] Durable subscriber can always resume from the last acknowledged/delivered cursor.
