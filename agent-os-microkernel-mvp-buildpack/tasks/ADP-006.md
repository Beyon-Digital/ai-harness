# ADP-006 — Implement adapter conformance harness and activation gate

**Phase:** `adapters`  
**Depends on:** [ADP-005](ADP-005.md)

## Goal

Run machine-readable port/capability tests before an external adapter can become eligible for profile/config resolution.

## Required outputs / expected code locations

- `crates/adapter-registry/src/conformance.rs`
- `crates/testkit/src/conformance.rs`
- `tests/adapter_conformance.rs`

## Normative inputs

- `DECISIONS.md`
- `contracts/` port/catalog contracts
- relevant component specs under `specs/`

## Implementation steps

1. Define `ConformanceReport` with exact bundle digest, port version, capability assertions, test IDs, result, timestamp/tool version.
2. Build reusable test packs for process protocol and fixture effect adapter.
3. For security-sensitive capabilities, tests verify behavior rather than declaration only.
4. Persist report/trust state in adapter registry.
5. Modify resolver to exclude required-review adapters without passing report.

## Required tests

- `fixture adapter conformance pass`
- `lying capability declaration fails`
- `protocol cancellation/deadline conformance`
- `bundle digest mutation invalidates prior report`

## Acceptance criteria

- [ ] Conformance report is bound to exact adapter ID/version/bundle digest.
- [ ] Resolver can require a passing conformance state.
- [ ] An adapter cannot advertise a stronger capability merely by editing its manifest after testing.

## Forbidden shortcuts

- Do not bypass the canonical port semantics to make the fixture pass.
- Do not claim durability/security capabilities not actually implemented.
- Follow all prohibited shortcuts in `AGENTS.md`.

## Completion evidence

Record exact tests and evidence in `TASK_STATUS.yaml`.
